## 2026-10-25 대량 시험: 공개 한글 파일 2,798개 + 실제 관공서 서식 149개 [도구 시험]

파일: 깃허브 공개 저장소(rhwp, python-hwpx, hwpjs, pyhwp, hwp.js)의 .hwp/.hwpx 2,649개 + 국가법령정보센터 별지 서식 149개(신청서·신고서·계약서), 같은 파일 뺀 2,798개.
파일마다: 읽기 → 문서 속 낱말 하나 바꾸기 → 같은 형식으로 저장 → 다시 읽어 글자 비교 → (hwpx) 구조 검사.

- 읽기 2,703개 성공. 못 연 것: 한글 3.0(1997년 이전) 68개, 암호·배포용 12개, 한글 파일이 아닌 빈/가짜 파일 6개, 깨진 파일 4개, 아주 큰 표 2개(2분 넘음). → 한글 3.0은 "한글에서 다시 저장해 달라"는 안내를 띄우게 함.
- 저장·다시 읽기: 바꾼 글자 말고는 글자가 하나도 안 바뀜(2,695개). 저장을 멈춘 6개는 한글이 거부할 수 있는 구조라 일부러 멈춘 것.
- 구조 검사 경고 157개는 **모두 원본 파일에 이미 있던 경고** (도구가 새로 만든 문제 0개).
- **찾아서 고친 것**
  1. 표 안의 표에 있는 글자를 찾아 바꾸기가 놓쳤다 → 우리 쪽에서 한 번 더 찾아 바꿈.
  2. XML 주석이 든 문서에서 저장 검사가 멈췄다 → 주석만 빼고 저장.
  3. .hwp로 옮길 수 없는 개체(깨진 OLE)가 든 문서 → 영어 오류 대신 ".hwpx로 저장하면 된다"는 안내.
  4. XML에 들어가면 안 되는 보이지 않는 글자가 든 기안문 서식(.hwpx) → 그 글자만 빼고 열어 고칠 수 있게 함.
  5. 짝 없는 반쪽 글자가 든 관공서 .hwp(2개) → 글자만 읽기로 넘어가게 하고, 고치기는 쉬운 말로 안 된다고 알림.
- **관공서 서식 표 칸 채우기** (흔한 칸 이름: 성명·주소·생년월일·전화번호·연락처·상호·대표자·사업자등록번호·신청인·소재지)
  - 처음(라이브러리 방식): 105개 중 25개만 완벽.
  - 칸 찾기를 새로 만듦: 오른쪽 빈칸 → 아래 빈칸 → 이름표 칸 안에 이어 쓰기, `묶음/이름표`, `이름표#번호`, 괄호 붙은 이름표, 셀 필드 이름.
  - 결과: **105개 중 101개 완벽**. 남은 4개는 "양도인"처럼 묶음 제목이라 어느 칸인지 골라 달라고 알려 주는 게 맞는 경우.
  - 한컴오피스 2024 한글 뷰어로 두 서식(납북피해 신고서, 채무승계 신고서)을 열어 정확한 칸에 들어간 것을 확인 [확인: 10-25].

## 2026-10-25 진짜 한컴 엔진(한컴오피스 2024 한글 뷰어)으로 확인 [확인: 10-25]

사용자 PC(Windows)에 무료 한컴오피스 뷰어를 깔고 시험 문서 6개를 열었다. 6개 모두 열렸다.
- 새 문서(.hwpx, .hwp): 제목·굵게·기울임·표 선·머리줄 색·글머리표(●, 2단계 ○ 들여쓰기)·번호·인용·가로줄 정상.
- 7MB 공문 찾아 바꾸기 결과: 75쪽·표지 그림 그대로, 바뀐 날짜 보임.
- 누름틀·표 칸 채운 문서, 명단으로 만든 신청서: 정상.
- **찾아서 고친 것 2가지**
  1. 가운데 맞춘 그림 뒤의 문단들(그림 설명, 다음 제목, 본문)이 가운데 맞춤을 물려받았다 → 새 문단은 항상 기본 문단 모양(0)으로 시작하게 고침.
  2. 그림 설명이 다음 쪽으로 떨어졌다 → 그림 문단에 "다음 문단과 함께" 켬.
  고친 뒤 한컴 뷰어로 다시 열어 둘 다 맞게 나오는 것을 확인.
- 폴라리스 뷰어는 1번 문제를 드러내지 않았다 → 마지막 확인은 한컴 뷰어로 해야 한다.

## 2026-10-24 그림 넣기·엑셀 명단 추가 [확인: 10-24]

- 그림: 2400px 큰 그림 → 쪽 폭(150mm)에 맞춤, 300px 작은 사진 → 원래 크기, webp → png로 바꿔 넣음, 세로로 아주 긴 그림 → 220mm 높이로 줄여 다음 쪽으로. 폴라리스 뷰어에서 4장 모두 제대로 보였다. .hwp로 저장해도 그림 4장 그대로.
- 없는 그림 경로 → [그림 없음: 경로] 글을 넣고 "주의"에 알림.
- 엑셀 명단: 첫 줄이 비어 있어도 첫 글자 있는 줄을 칸 이름으로, 빈 줄은 건너뜀, 날짜 칸은 2026-10-25, 31.0은 31로.
- 엑셀에서 한 번도 안 연 파일의 계산식 칸은 값이 비어 있다 → 어느 칸인지 알려 주게 함.

## 2026-10-24 다른 회사 뷰어로 열어 봄 [확인: 10-24]

- 새로 만든 `계획서.hwpx`를 폴라리스 오피스 HWPX 뷰어(무료, 로그인 없음)로 열었다. 제목·굵게·기울임·표 선·머리줄 색·글머리표(●/○)·번호(1. 2. 3.)·인용·가로줄 모두 제대로 보였다. → 우리 미리 보기에서 안 보이던 것들이 실제 파일에는 잘 들어 있다는 것을 확인.
- 고친 것: 2단계 글머리표(○)가 들여 써지지 않았다 → 2단계부터 7mm씩 들여 쓰게 고침.
- 같은 뷰어로 더 열어 봄: 새로 만든 `.hwp`(바이너리) 정상 / 7MB 실제 공문을 찾아 바꾸기 한 결과 75쪽·그림·표지 그대로, 바뀐 날짜 보임 / 누름틀 "날짜"와 표 "합계" 칸 채운 결과 정상.

## 2026-10-24 처음 만듦 [도구 시험]

시험 파일: 공개 한글 시험 파일 93개(hwplib 샘플 .hwp 33개, hwpxlib 시험 .hwpx 49개 등)와 직접 만든 계획서·신청서.

- 읽기: 91/93 성공. 실패 2개 = 배포용 잠금 파일(정상 거부), 85MB짜리 큰 파일(예비 방식으로 글자만 읽음).
- hwpx로 다시 저장: 89/91. 실패 2개(`etc.hwp`, `필드.hwp`)는 종류를 모르는 필드가 있어 "한글이 거부할 수 있다"며 저장을 멈춤 — 깨진 파일을 만들지 않으니 맞는 행동.
- hwp로 다시 저장: 89/91, 89개 모두 다시 읽은 글자가 원본과 완전히 같음.
- 실제 공문(재난안전 분석, 7.2MB, 표 109개, 그림 75개)에서 찾아 바꾸기 154곳 — 87개 부품 중 바뀐 것은 본문 2개뿐. 8초 걸림.
- 양식 채우기: `{{이름}}` 빈칸, "성명 > right" 표 칸, 누름틀 "날짜" 모두 채워짐.
- 여러 장 만들기: CP949(엑셀 기본) CSV 명단으로 3장, 한글 빈칸 이름도 됨. (라이브러리 자체 기능은 영어 빈칸 이름만 알아서 직접 만듦)
- 마크다운 → 새 문서: 구조 검사 통과. 미리 보기에는 글머리표·번호·표 선·가로줄이 안 그려지지만 파일 XML에는 들어 있음(글머리표 ●/○, 번호, 표 테두리 SOLID 확인).
